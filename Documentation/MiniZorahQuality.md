# MiniZorah 1.5 px 质量收敛

日期：2026-09-13。完整 MiniZorah cook、1920×1080、1 GiB 页面预算、1.5 px 目标、RelWithDebInfo、RTX 5070 Ti / 616.64、Vulkan validation、异步 HW/SW。

本轮实现包含全部细化后代的保守需求包围盒，停止为完全位于视口外的细节持续申请页面。三个固定视角通过“5 秒内可见超标 refinement 归零、随后保持”的验收。运动中的新可见区域仍有加载瞬态，因此不宣称每个运动帧都满足 1.5 px。

## 固定视角验收

| 固定相机（既有漫游路线时间） | 首个收敛检查点，累计渲染秒 | 稳态最大可见误差 / px | 稳态有效驻留 / MiB |
| --- | ---: | ---: | ---: |
| 起点，0 秒 | 1.507 | 1.499921 | 251.97 |
| 近景，15 秒 | 1.508 | 1.499972 | 238.39 |
| 转向，35 秒 | 1.500 | 1.499958 | 196.05 |

每个视角运行 30 秒，前 5 秒每 0.5 秒检查，此后每 5 秒检查，末次检查在 25 秒。收敛后所有检查点的可见超标组和近裁面无界组均为 0。时间是检查点观测上界，排除初始化和检查点验证；起点/转向对应的实际墙钟时间为 2.095 / 2.046 秒，近景首次测量未记录墙钟。它们不是逐页 request→drawable 延迟测量。

近景原实现同样在 5 秒检查点已满足质量目标，但页面池占满后仍每帧请求 2,988 个无法容纳的页面。需求裁剪消除了这些持续请求，保留相同可见结果：25 秒 MaterialResolve 图像逐像素比较，**2,073,600 个像素中差异数为 0**。

| 近景 30 秒对照 | 原需求规则 | 后代范围需求裁剪 |
| --- | ---: | ---: |
| 有效驻留 / MiB | 1,023.40 | 238.39 |
| 选中 cluster | 437,644 | 213,532 |
| early 候选 | 411,041 | 187,000 |
| early HW / SW cluster | 40,334 / 24,356 | 40,334 / 24,356 |
| GPU P95 / ms | 13.168 | 9.102 |
| 同步离屏帧 P95 / ms | 18.142 | 12.685 |
| CPU record P95 / ms | 5.827 | 3.920 |

以上时序是 GPUDriven + MaterialResolve，同步离屏执行，排除呈现 blit、计时帧图像/调试回读和检查点验证，不代表编辑器呈现 FPS。近景两次实验检查点频率不同，不据此推断冷启动收敛速度提升。页面池仍预留 1 GiB；有效驻留下降不等于释放了同等物理显存。

## 实现与质量定义

- 按 group 的细到粗顺序，对自身误差扩展球的 AABB 与全部子组范围取并集。共享子组进入每一个父组的范围，防止只裁掉父组自身球而阻断可见细节。terminal 的无限误差哨兵不参与范围扩张，根页继续保留。
- GPU 对变换后的包围盒进行 near/far、四个侧面测试，包含剪切、非均匀缩放、正交投影、向外舍入和浮点消差余量。额外留一像素视口边界。不可表示的范围保守保留。
- 三种 frontier 路径都应用该规则。页面真正 drawable、全部父组 active 后才替换旧 cut，继续保持完整根覆盖和共享父组一致性。手动 LOD 保持原有行为。
- `viewDrivenPageDemand` 默认开启；设为 `false` 可做旧需求规则对照。cook 文件、payload、LOD 误差公式和 1.5 px 阈值均保持原值。
- 运行时每组增加 24 B 元数据，本场景共增加 32,567,016 B（31.06 MiB）。不会每帧在 CPU 重建包围盒。

验收从 GPU 实际输出的 cut 重建共享 DAG，检查缺口、重复覆盖、不可达组及容量回退；随后对仍由粗 cluster 表示的 refinement 使用原有投影误差公式。只有其自身误差扩展范围与视口相交时才计入可见质量，包含被遮挡但在视锥内的范围，未使用 HZB 掩盖误差。旧的全场景超标计数继续保留，它包含屏外和相机背后的范围，不能用作屏幕质量结论。

这是 **cook 所提供几何误差度量下的可见 cut 收敛**，不是与全部原始三角形逐像素比较所得的几何真值保证。视口外仍可保留较粗但完整的几何。

不受驻留限制的 CPU 审计覆盖起点、前移、转向三个视角：原需求的活动页有效载荷为 16.94 / 18.86 / 23.62 GiB，新规则为 277.94 / 262.40 / 240.04 MiB，全部可见需求保留。这些审计视角与固定路线相机略有不同，且审计包含所有源可见实例，因此不能直接当作 GPU 实际驻留量。球体测试额外保留的空区域单独报告为 `sphereOnlyPruned`。

## 连续漫游与压力预算

180 秒三轮路线完成 18,367 个计时帧、36 个检查点。全程预算、实例/相机传递、DAG 完整 cut、early/late 候选和页面请求合法性均通过；没有加载失败、无效请求或页面驱逐。GPU P95 为 8.746 ms，同步离屏帧 P95 为 12.415 ms，CPU record P95 为 4.519 ms。

首轮除启动外，可见超标 refinement 在检查点为 0～147 个，其中 25 秒从远景切回近景的记录最多。第二轮 60 秒检查点剩 1 个；**65～175 秒的 23 个检查点全部为 0**。质量回读按检查点进行，不把这些结果扩大为所有运动帧的保证。

| 相同 55 秒路线检查点 | 原需求规则 | 新需求规则 |
| --- | ---: | ---: |
| 累计上传 / MB，十进制 | 3,988.79 | 601.94 |
| 累计页面驱逐 | 74,740 | 0 |
| 可见超标 refinement | 326 | 0 |

上传下降 84.9%。新规则 175 秒时有效驻留为 577.85 MiB，累计上传 603.38 MB；55～175 秒仅再上传 1.44 MB。原需求规则对照运行 60 秒，新规则运行 180 秒，时序百分位不按这两个不同长度直接计算提速比例。进程本地显存末次读数约 2.294 GiB，包含预留页面池和新增元数据。

64 MiB、60 秒压力路线继续保持预算和完整回退，55 秒有效驻留 62.18 MiB，累计上传 213.76 MB、驱逐 12,669 页。但可见超标 refinement 为 3,679 个，其中近裁面无界 126 个，**不满足质量目标**。

本轮持续测试为 180 秒；上一轮的 660 秒报告属于旧需求策略，不当作新版本十分钟验收。

最终 **35 项相关回归通过**，其中 GPU/CPU cut 对照扩展为 292 组，覆盖完整/部分驻留、共享父组、相机切换、正交/透视/窄视口、剪切、手动 LOD、稀疏状态复用与容量回退；完整 MiniZorah VBuffer 和需求审计亦通过。`Metallic`、`MetallicGPUDrivenSample`、`MetallicRhiTests` 构建成功。结构化结果与原始报告哈希见 [MiniZorahQualityResult.json](MiniZorahQualityResult.json)。

## 下一步

1. 用逐页首次需求、依赖就绪和 drawable 帧号区分冷启动、转向后依赖加载与 CPU/I/O 等待，量化尾延迟；检查点收敛时间不能代替这些指标。
2. 在同样质量约束下试验小幅运动预取和视口边缘滞后，减少首轮切换瞬态，同时约束上传量和驻留增量。
3. 已测三轮工作集可以容纳于 1 GiB，压缩暂不作为达到本资产质量目标的前置条件。继续优化 early 分类和候选准备，再用更紧预算决定压缩投入。

## 复现

在测试构建中运行：

```powershell
$env:METALLIC_TEST_MINIZORAH='1'
$env:METALLIC_MINIZORAH_ROAM_MIB='1024'
$env:METALLIC_MINIZORAH_ROAM_SECONDS='30'
$env:METALLIC_MINIZORAH_FIXED_VIEW='15' # 0 / 15 / 35
$env:METALLIC_MINIZORAH_VIEW_DEMAND='1' # 0 为原需求规则
build-relwithdebinfo/tests/MetallicRhiTests.exe --gtest_filter=RhiRendering.minizorah_roaming --rhi-validation --rhi-async-compute --output-dir build-relwithdebinfo/minizorah-quality/repro
```

固定相机在至少 1 GiB 时默认强制 5 秒收敛期限；`METALLIC_MINIZORAH_CONVERGENCE_SECONDS` 可显式指定期限。移除 `METALLIC_MINIZORAH_FIXED_VIEW` 后运行原 60 秒循环路线。64 MiB 压力测试只验收完整回退和预算，不自动套用固定视角质量期限。

原始输出位于 `build-relwithdebinfo/minizorah-quality/`，包括质量审计、GPU 时间、完整 cut 检查和图像。
